**Created:** 2026-09-10

## Context

The plugin's doctrine has grown past what an agent needs at the moment it acts: a single two-skill BUILD dispatch loads ~7,600 words of skill text plus 1,831 (build-agent) plus a 2,580-word template file, and `commands/build.md` narrates seven SETUP sub-steps and a four-part VERIFY before and after the work. The owner wants it "a little bit lighter": less repetition and less ceremony, **not fewer rules**. The test for every deletion is whether the same rule still exists somewhere the acting agent actually reads at that moment — a rule moved to a file nobody loads is a rule lost.

Brief: `/private/tmp/claude-501/-Users-r-repos-code-foundations/477ae14e-601c-4ae1-b769-1bb3a2e73bb1/scratchpad/lighten-brief.md`. Requirements picture (what:what-for) and options spread (what:what-else) were produced 2026-09-10 and folded in below.

## Constraints
- Branch `feat/lighten` only; no merge, no push. One conventional commit per phase (`references/commit-format.md` subject/body rules; the build trailers do not apply — this plan is executed by hand, not by `/code-foundations:build`).
- Every bundled skill file linked from its SKILL.md; all 19 skills `user-invocable: false`; `planning` keeps `disable-model-invocation: true`; braced `${CLAUDE_PLUGIN_ROOT}` / `${CLAUDE_SKILL_DIR}` paths only; `docs/code-standards.md` governs authoring.
- **Skill `description:` fields are byte-identical before and after** (they are the trigger surface; `test_triggers` is a regression guard only).
- Keep: the EXECUTE loop, the v6.3.0 batch-review cadence, the security-sensitive 3-sample REVIEW, the trust report, the deliberately duplicated REVIEW debias rule (build.md + dispatch-templates § REVIEW), and the deliberately inline Gate Policy / Model Resolution / Skill Resolution / Execution Loop in build.md (grug `build-command-progressive-disclosure`).
- Cross-references between build.md, plan.md, planning/SKILL.md, agents/*, references/*, CLAUDE.md, README.md stay consistent — each phase updates every file that names what it changed.
- Minor version bump (6.3.0 → 6.4.0): build behavior changes.
- Every phase may also edit `evals/inventory-dropped.tsv`, `evals/rules-registry.tsv`, and this plan's execution log — the ledger and the log are per-phase deliverables, not scope overruns.

## Decisions taken on the two owner-flagged items
1. **Checklist `### Standard` tier items: keep them.** Only one checklist file has a `### Standard` heading at all — `cc-defensive-programming/checklists.md`, holding GS-1..GS-4 (debugging aids, amount of defensive code, offensive programming; ~60 words). The modern security items (SM-*) and async items (SA-*) sit under `### Critical - Modern Threats` and `### High Priority`; only the deleted Priority Groups tail ever called them "Standard". So dropping the tier would save nothing measurable while still changing what gets checked. Kept; deferred to the owner with this corrected reading in the final report; no commit touches it.
2. **Effort Alignment stop → non-blocking one-line warning.** The safe reversible default from the brief. The depth-steering table stays under the same heading (dispatch-templates and plan-integration name it as the source rule), the mismatch table collapses to one sentence, and nothing blocks. Reverting is a one-hunk change.

## Success criteria (pre-declared)
- Core plugin markdown (skills+commands+agents+references+docs+CLAUDE.md+README.md, baseline 91,464 words): **≥ 10% smaller**; and the dispatch-relevant set (the same minus `skills/gof-design-patterns/references/**`, which is lazy-loaded pattern material the plan leaves untouched — baseline 63,264): **≥ 15% smaller**. (Re-stated after the what-if probe summed the named cuts at ~10,000 words; declared here before any phase past 1.)
- Representative two-skill BUILD dispatch load (build-agent + § FULL_BUILD + cc-defensive-programming + cc-routine-and-class-design with everything they `Read`): **≥ 30% smaller** (`evals/dispatch-load.sh`).
- `evals/validate-structure.mjs` clean; `validate_skill` 0 errors on 19/19; descriptions byte-identical; `what-breaks` returns nothing above nit on every phase diff.
- **Independent rule inventory (check J):** every checklist item ID (`XX-N:`) and every `##`/`###` heading in skills/, agents/, commands/, references/ on the pre-cut commit is either still present in the same file or listed in `evals/inventory-dropped.tsv` with the item/section that now carries it (or "dropped — reason"). The inventory is extracted from `main` by script, not written by the cutter, so an item the cutter never noticed fails the validator.
- CHECKER A/B (`evals/checker-eval`): trimmed cc-defensive-programming reports all 7 planted violations and not the clean function in every run; verdict rule: any planted violation missed in ≥ 2 of 3 runs by the trimmed arm but caught by the old arm = regression → fix before proceeding. N=3 per arm; this detects gross recall loss only, not subtle degradation.
- Build-workflow smoke: a fresh Explore agent executes the collapsed SETUP and VERIFY from the doc alone against `evals/build-smoke/` with no unresolvable ambiguity.
